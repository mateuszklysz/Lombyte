# Overlay configuration

Map metadata for the per-level overlay programs (EE code) that the game
streams into the same RAM arena as the boot executable's game code.

- `us/level-table.json` — hidden ToC level table for the USA retail ISO
  (`LEVELn.WAD` byte offset/size per level), schema
  `rnc-overlay-level-table-v1`. Recovered 2026-09-16 with wrench v0.5
  `inspect_iso`; includes the ISO sha256 and tool provenance. Level names are
  community reference metadata, not game evidence.
- `us/index.json` — generated overlay map index, schema `rnc-overlay-map-v1`:
  per level entry point, sections, ELF sha256, MIPS prologue count and overlap
  with the boot executable's code window.
- `us/level-NN.json` — per-level detail behind `index.json`.
- `us/names/level-NN.json` — transferred naming evidence per level, schema
  `rnc-overlay-name-evidence-v1`: exact-boot-match names (recovered boot
  symbols) and preview-match links with module/assert context where it
  survived. Not semantic proof; method and provenance are recorded per row.

Rules:

- Code only: these files describe the overlay ELF programs, not level assets.
- Overlay addresses collide with the boot game-code window. Unit identities are
  namespaced `overlay/us/level-NN/FUN_XXXXXXXX` and must never be merged into
  `us/rnc1.us.yaml`.
- No game bytes are committed; extracted ELFs live in the tooling repository,
  never here.
- Regenerated by the tooling repository's overlay extraction/audit scripts.
