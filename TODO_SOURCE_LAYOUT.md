# Source layout follow-up

Scope: public game sources under `src/`. The first semantic-layout pass is in
place; this checklist keeps the remaining classification work visible.

## Completed in the current branch

- [x] Moved 341 of the 528 C units outside `textbin/` into semantic directories.
- [x] Kept the remaining 187 units under existing semantic `math/` and `sdk/`
  modules; left `textbin/` and `assembly/textbin/` paths untouched.
- [x] Replaced the old top-level `core`, `ee`, `gs`, `kernel`, and `sys`
  ownership folders with `runtime/`, `rendering/`, `gameplay/`, `storage/`,
  `video/`, and `sdk/` groups. `assembly/` remains as the source-state marker.
- [x] Split SDK files into `debug`, `dma`, `input`, `rpc`, `storage`, `system`,
  `time`, and `video` modules. Renamed `deci_debug`, `dma_ipu_gs`, and
  `sif_rpc` to those semantic module names.
- [x] Updated linker owners, recovered-name paths, compiler routes, category
  metadata, and generated progress reports. Assembly-backed sources still
  include their owner-specific generated oracle.
- [x] Keep flat, unnamed textbin owners in one explicit `unclassified` group
  instead of assigning them arbitrary address-range labels.

## Follow-up work

- [ ] Review the functions in `unclassified` using symbols, callgraph, and
  recovered-name evidence. Move a function into a subsystem only when the
  assignment is supported; keep genuinely unknown functions in this group.
- [ ] Review the broad `sdk/library` group (184 functions, 65,520 bytes) for
  proven library families that can become smaller groups without guessing.
- [ ] Recheck the initial name-based placements in `runtime/state`,
  `runtime/resources`, `sdk/system`, and `sdk/dma` against function behavior
  and callsites.
- [ ] Remove this checklist when the remaining review items are closed.

## Current display outputs

`assets/decomp_map.svg` and `assets/decomp_map.json` are generated by
`scripts/generate_treemap.py`; the SVG presents a Game/SDK hierarchy, with the
SDK panel occupying one quarter of the map. `progress/report.json` is generated
by `scripts/gen_progress_report.py` and supplies the clickable groups and
member functions shown by decomp.dev.
